## 1. Project overview

### Purpose
Data Detective is a LangGraph agent that audits a CSV dataset (missing values, duplicates, imbalance, leakage, bias, drift) and produces an evidence-based report before any model is trained. Built alongside the CampusX "Agentic AI using LangGraph" playlist.

### Tech stack / dependencies (`pyproject.toml`, `requires-python = ">=3.13"`)
- Language: Python 3.13+
- Agent framework: LangGraph + LangChain
- LLM provider: Ollama (`langchain-ollama`), default model `llama3.1:8b`, `ChatOllama` at `http://localhost:11434`, temperature 0.0
- Data tools: pandas, numpy, scikit-learn, scipy
- Backend/API: FastAPI, Streamlit, pydantic, pydantic-settings
- Database: PostgreSQL + SQLAlchemy + `psycopg[binary]` + `langgraph-checkpoint-postgres` (PostgresSaver checkpointer)
- Testing: pytest, pytest-asyncio

### How to run (`main.py`)
```
python main.py data/raw/adult.csv --target income
python main.py data/raw/adult.csv --target income --agent          # M4 LLM ReAct agent mode
python main.py --list                                              # list past runs from PostgreSQL
python main.py data/raw/adult.csv --target income --thread-id run-001
python main.py data/raw/adult.csv --target income --sensitive sex --favorable ">50K"
python main.py data/raw/adult.csv --target income --semantic-override SeniorCitizen=binary
python main.py --workbench visualize --run-id <uuid>               # Phase 2 charts (alias: --visualize)
```
Every run requires a live PostgreSQL instance (`.env` supplies `DATABASE_URL`); results are saved to Postgres business tables plus LangGraph checkpoints. `main.py` prints the plain-text report to stdout.

### Conventions from AGENTS.md / the brief (fully summarized)

1. **The LLM never sees the full CSV** — only a compact summary (column names, types, missing counts, basic stats, a few sample rows). Enforced by `build_llm_digest` (token budget ~2000 tokens, degrades gracefully).
2. **Python tools do the calculations** — pandas/scikit-learn compute; the LLM decides what to check and explains results.
3. **LangGraph state holds IDs, file paths, findings — never a DataFrame.** Tools load the CSV from disk.
4. **Every finding is a structured Pydantic `Finding`** with `check_name`, `severity`, `evidence`, `affected_columns`, `confidence` (note: the actual `Finding` model has no `suggested_fix` field despite the brief listing it).
5. **Claims need proof** — e.g., a leakage claim needs a baseline model result (the leakage check does CV ROC AUC / R^2 with a Dummy baseline).
6. **The agent never changes the user's data without human approval** — no write-back to CSVs; all output is reports/charts.
7. **Code style:** Python with type hints, small single-purpose functions, pure/testable check functions (input path or DataFrame loaded inside tool, output `Finding` list).
8. **Repo layout:** graph code in `src/graph/`, checks in `src/tools/checks/`, models in `src/schemas/`, API in `src/api/`, DB in `src/db/`, evaluation in `eval/`.
9. **Testing:** add a simple test in `tests/` for each new check function. `Finding.__lt__` sorts by severity (CRITICAL first).
10. **Config/secrets in `.env`, never in code** — `src/config.py` uses `pydantic-settings` with `.env`.
11. **Comment cleanup rules:** remove obvious/restating comments; keep only *why* explanations (max 1–2 sentences); brief docstrings 3–4 sentences max; zero logic changes when cleaning comments.
12. **Do-not rules:** never touch raw data in `data/raw/`, never touch `.env`/secrets, never print or commit API keys. Do not generate the whole project unasked (student writes code). Do not jump ahead of the current milestone. Ask before adding dependencies, renaming/moving files, changing graph structure, changing DB tables, or deleting anything.

## 2. Main LangGraph pipeline

Two compiled graphs live in `src/graph/builder.py`.

### Graph A — `build_graph(checkpointer=None)` (deterministic, default)

Flow: `START -> load_csv -> profile -> [8 parallel checks] -> merge_findings -> router -> (deep_checks?) -> report -> END`

| Node | File | Function | Reads from state | Writes to state |
|------|------|----------|------------------|-----------------|
| `load_csv` | `src/graph/nodes.py:33` | `load_csv_node(state)` | `csv_path` | `csv_path` (normalized), `dataset_id` (= `path.stem`), `error` (None or message) |
| `profile` | `src/graph/nodes.py:354` | `profile_node(state)` | `csv_path`, `target_column`, `semantic_overrides` | `profile` (dict from `profile_dataset`), `error` |
| `check_<name>` ×8 | `src/graph/nodes.py:106` | `make_check_node(spec)` → `_run_registered_check` → `run_check` | `csv_path`, `target_column`, `profile`, `check_params[name]` | `findings` (list of Finding dicts, appended via reducer) |
| `merge_findings` | `src/graph/nodes.py:121` | `merge_findings_node(state)` | — (no-op passthrough) | `{}` (reducer does the merge) |
| `router` | `src/graph/nodes.py:131` | `router_node(state)` | `findings`, `target_column` | `leakage_suspected` (bool), `suspect_columns` (list) |
| `deep_checks` | `src/graph/nodes.py:159` | `deep_checks_node(state)` | `csv_path`, `target_column`, `check_params` | `deep_check_results` (list), `findings` (leakage findings) |
| `report` | `src/graph/nodes.py:373` | `report_node(state)` | `profile`, `dataset_id`, `error`, `findings`, `deep_check_results`, `summary`, `overall_severity` | `report` (JSON string), `report_text` (plain text) |

Conditional edges:
- `load_csv` → `_go_unless_error("profile")`: `"profile"` unless `error`, else `"report"`.
- `profile` → `_fan_out_unless_error(check_node_names)`: fan-out to all 8 `check_*` nodes unless error, else `"report"`.
- `router` → `lambda state: "deep_checks" if state.get("leakage_suspected") else "report"`.
- All `check_*` → `merge_findings`; `merge_findings` → `router`; `deep_checks` → `report`; `report` → `END`.

### Graph B — `build_agent_graph(llm=None, checkpointer=None)` (M4 LLM agent)

Flow: `START -> load_csv -> profile -> agent_checks -> deep_checks -> synthesize -> report -> END`

| Node | File | Function | Reads | Writes |
|------|------|----------|-------|--------|
| `load_csv`, `profile` | as above | same | same | same |

### The semantic-column-meaning step

`profile_node` calls `profile_dataset(csv_path, target_column, overrides)` (`src/tools/profiling.py:532`), which:
1. Loads CSV via `read_csv_robust`.
2. Computes `n_rows`, `n_cols`, `duplicate_rows`.
3. For each column, `_profile_column` builds `{name, dtype, missing, missing_pct, text_markers}` plus either `stats` (numeric: min/max/mean/std), `type_category`+`true_count`+`true_pct` (boolean), or `unique`+`sample_values` (text).
4. Second pass `classify_columns` → `_classify_column_unwrapped` per column yields `semantic = {type, confidence, ambiguous, reasons}` over 10 types (`SEMANTIC_TYPES`: `numeric_measurement`, `numeric_discrete`, `binary`, `categorical`, `ordinal_candidate`, `datetime`, `identifier`, `text`, `constant`, `unknown`).
5. Sets `target_type` via `detect_target_type` if target given; `sample_rows = df.head(3).to_dict(orient="records")`.

Overrides (name → type, validated against `SEMANTIC_TYPES`) win over every classifier rule: `result["type"]=new_type`, `confidence=1.0`, `ambiguous=False`.

### Tool-selection fan-out (agent mode)

`src/graph/tools.py` builds `ALL_TOOLS` — one LangChain `StructuredTool` per registry check with `agent_tool=True`. All 9 registered checks are agent tools (8 parallel + `target_leakage` which is `parallel=False`):

| Tool name | Check name | File | What it computes | Return shape |
|-----------|------------|------|------------------|--------------|
| `run_schema_check` | `schema` | `src/tools/checks/schema_check.py` | Text columns >80% numeric-like | JSON string of `list[Finding]` |
| `run_missing_check` | `missing_values` | `src/tools/checks/missing_check.py` | Missing (NaN + text markers) count/ratio per column; LOW/HIGH/CRITICAL | JSON string of `list[Finding]` |
| `run_duplicates_check` | `duplicates` | `src/tools/checks/duplicates_check.py` | Duplicate row count/% | JSON string of `list[Finding]` |
| `run_id_like_check` | `id_like` | `src/tools/checks/id_like_check.py` | Non-target columns unique per row | JSON string of `list[Finding]` |
| `run_class_imbalance_check` | `class_imbalance` | `src/tools/checks/imbalance_check.py` | Target minority share; HIGH <10%, MEDIUM <30% | JSON string of `list[Finding]` |
| `run_skewness_check` | `skewness` | `src/tools/checks/skewness_check.py` | \|skew\| of `numeric_measurement`/`numeric_discrete` columns | JSON string of `list[Finding]` |
| `run_outlier_check` | `outliers` | `src/tools/checks/outlier_check.py` | IQR outlier % per numeric column | JSON string of `list[Finding]` |
| `run_bias_check` | `bias` | `src/tools/checks/bias_check.py` | Disparate impact across user-specified sensitive groups (binary target only) | JSON string of `list[Finding]` |
| `run_leakage_check` | `target_leakage` | `src/tools/checks/leakage_check.py` | Single-column CV ROC AUC / R^2 vs target vs Dummy baseline | JSON string of `list[Finding]` |

Tools are built dynamically from the registry (`_make_tool` per `CheckSpec`); `run_check` loads the CSV once centrally and applies target-type and semantic gating. Tool results serialize to JSON via `_serialize` (`f.model_dump(mode="json")`) and are parsed back via `_parse`.

### The leakage router

`router_node` (`src/graph/nodes.py:131`) scans merged findings; a column is "suspected" if it appears in an `id_like` finding or a `schema` finding (numbers-as-text), excluding the target column. Sets:
- `leakage_suspected = len(suspect_columns) > 0`
- `suspect_columns` = list of suspect column names.

**No numeric threshold** — mere presence of an id_like/schema finding on a non-target column triggers suspicion.

`deep_checks_node` (`src/graph/nodes.py:159`) runs `target_leakage`. **Quirk:** it passes `suspicious_columns=None`, so `leakage_check` tests *all* non-target columns, not just the router's suspects. The router's `suspect_columns` is recorded in state but not used to limit the deep check.

`leakage_check` (`src/tools/checks/leakage_check.py`) trains a per-column scikit-learn `Pipeline` (impute + one-hot or median-impute + LogisticRegression/LinearRegression) with 5-fold stratified CV (ROC AUC / one-vs-rest for classification, R^2 for regression). Thresholds (`check_config.leakage`): critical AUC ≥0.98 / R^2 ≥0.98; high AUC ≥0.92 / R^2 ≥0.90; medium AUC ≥0.85 / R^2 ≥0.70. Reports a Dummy-model baseline for comparison (proof requirement). Skips constant columns and high-cardinality columns (≥0.9 unique ratio when n_rows ≥ 50).

### The report node

`report_node` (`src/graph/nodes.py:373`) builds one `AuditReport` (`src/schemas/report.py`):
- `dataset_id`, `rows`, `cols`, `duplicate_rows`, `summary`, `overall_severity`, `findings` (list of `Finding`), `columns` (list of per-column dicts from profile), `sample_rows` (first 3 rows as records), `deep_check_results`, `error`, `generated_at` (UTC ISO).

Writes to state:
- `report` = `report_obj.to_json()` — **canonical JSON string** (single source of truth).
- `report_text` = `render_text_report(report_obj)` — plain text (Dataset, rows/cols, duplicates, summary, findings sorted by severity, deep leakage results, columns with dtype/missing/stats, sample rows).

**Persistence:** `main.py` calls `save_run(...)` (`src/db/repository.py`) storing `report_json` and `report_text` in PostgreSQL `reports` table (JSONB), plus `findings` rows. Graph state is also checkpointed by `PostgresSaver`. The report is **not** saved to a flat file by V1; only plots (visualizer) write files.

## 3. Existing dataset profiling (MOST IMPORTANT)

Every function/module/tool that computes per-column or per-dataset facts:

### 3.1 `src/tools/csv_reader.py`
- `read_csv_robust(csv_path: str) -> pd.DataFrame` — loads CSV with encoding fallback (utf-8, utf-8-sig, latin-1, cp1252), delimiter detection (`,`, `\t`, `;`, `|`), BOM stripping, column-name stripping, LRU-cached (maxsize=3), returns isolated copy. **Called by:** `profile_dataset`, every check via `run_check`, visualizer `_load_csv`.
- Helpers: `_read_csv_robust_impl`, `_detect_delimiter`.

### 3.2 `src/tools/missing_markers.py`
- `count_missing(series: pd.Series, extra_markers=None) -> tuple[int, int]` — returns `(nan_count, marker_count)` where markers are matched against `MISSING_MARKERS` (frozenset: `?, NA, N/A, null, NULL, "", " ", -, --`), string columns only. **Called by:** `_profile_column`, visualizer `_semantic_or_stop`.
- `MISSING_MARKERS`, `DEFAULT_MISSING_MARKERS` (configurable via `DATA_DETECTIVE_MISSING_MARKERS` env var).

### 3.3 `src/tools/profiling.py` — the V1 profiler (the core profiling module)
- `profile_dataset(csv_path: str \| Path, target_column: str \| None = None, overrides: dict[str, str] \| None = None) -> dict[str, Any]` — top-level profile. Returns:
  ```python
  {
    "n_rows": int, "n_cols": int, "duplicate_rows": int,
    "columns": [ {per-column dict} ],
    "target_type": str,            # binary/multiclass/continuous/boolean/unknown
    "sample_rows": [dict, ...]     # first 3 rows as records
  }
  ```
- `_profile_column(series: pd.Series) -> dict[str, Any]` — per column:
  ```python
  {
    "name": str,
    "dtype": str,
    "missing": int,                # NaN + text markers
    "missing_pct": float,
    "text_markers": int,
    # numeric only:
    "stats": {"min", "max", "mean", "std"},
    # boolean only:
    "type_category": "boolean", "true_count": int, "true_pct": float,
    # text only:
    "unique": int, "sample_values": [str, ...],
  }
  ```
  **Notes:** numeric columns get `stats` but **no `nunique` and no `skew`** in V1. Text columns get `unique`/`sample_values` but no stats.
- `classify_column(series, col_info=None, column_series=None, config=None) -> dict[str, Any]` — public wrapper; returns `{type, confidence, ambiguous, reasons}` (≤2 reasons).
- `classify_columns(df, columns_info, target_column=None, overrides=None, config=None) -> list[dict]` — second pass; applies overrides (name→type wins, confidence=1.0).
- `get_semantic_lookup(profile) -> dict[str, dict[str, Any]]` — `{column_name: semantic_dict}`; tolerant of missing keys.
- Internal classifiers: `_classify_column_unwrapped` (rules: all-missing→unknown; nunique≤1→constant; small-sample→dtype-only ambiguous; datetime via dtype or date-parse-ratio≥0.8; binary=nunique==2; numeric path if numeric-parse-ratio≥0.9 else string path; `_classify_numeric` handles identifier/row-identifier/4-digit-code/near-unique/encoded-duplicate/numeric_discrete/numeric_measurement; `_classify_string` handles identifier vs text vs categorical by unique ratio).
- `SEMANTIC_TYPES = ("numeric_measurement","numeric_discrete","binary","categorical","ordinal_candidate","datetime","identifier","text","constant","unknown")`.

### 3.4 `src/tools/target_type.py`
- `detect_target_type(series: pd.Series) -> str` — `boolean` if bool dtype; `binary` if nunique==2; `continuous` if numeric and nunique/n_rows > 0.1 (`check_config.target_type.continuous_unique_ratio`); `multiclass` otherwise; `unknown` if empty/nunique≤1.

### 3.5 `src/tools/checks/` — each check computes per-column/dataset facts

| Check | File | Signature | Facts computed | Thresholds (`check_config`) |
|-------|------|-----------|----------------|-----------------------------|
| `schema_check` | schema_check.py | `(df, target_column=None) -> list[Finding]` | text columns >80% numeric-like | `schema.numeric_pct_threshold=0.8` → MEDIUM |
| `missing_check` | missing_check.py | `(df, target_column=None)` | missing count & % per column (NaN + markers) | >50% CRITICAL, >20% HIGH, else LOW |
| `duplicates_check` | duplicates_check.py | `(df, target_column=None)` | duplicate row count & % | >10% HIGH else MEDIUM |
| `id_like_check` | id_like_check.py | `(df, target_column=None)` | non-target columns unique per row | `unique_count == n_rows` → MEDIUM |
| `imbalance_check` | imbalance_check.py | `(df, target_column=None)` | target minority share | <10% HIGH, <30% MEDIUM, else none |
| `skewness_check` | skewness_check.py | `(df, target_column=None)` | \|skew\| of `numeric_measurement`/`numeric_discrete` cols | >2.0 HIGH, >1.0 MEDIUM |
| `outlier_check` | outlier_check.py | `(df, target_column=None)` | IQR outlier % per numeric col | >10% HIGH, >5% MEDIUM |
| `leakage_check` | leakage_check.py | `(df, target_column, suspicious_columns=None)` | per-column CV ROC AUC / R^2 vs Dummy baseline | AUC ≥0.98 CRITICAL, ≥0.92 HIGH, ≥0.85 MEDIUM; R^2 ≥0.98/0.90/0.70 |
| `bias_check` | bias_check.py | `(df, target_column, sensitive_columns=None, favorable_value=None)` | per sensitive group: favorable rate, n, disparate impact, chi-square p | DI<0.4 CRITICAL, <0.6 HIGH, <0.8 MEDIUM; p<0.01 significant |

### 3.6 `src/tools/checks/registry.py`
- `run_check(spec, state, run_fn=None)` — central runner: loads CSV once, applies required-input gating (missing input → one INFO note), target-type gating (unsupported type → INFO skip), semantic gating via `get_semantic_lookup` (filters df to eligible columns + target, emits skip note). Returns `list[Finding]`.

## 9. Risks and quirks

1. **Semantic classifier.** V1 (`src/tools/profiling.py`, 10 types, thresholds e.g. `DISCRETE_MAX_UNIQUE=20`, `CARDINALITY_RATIO=0.05`, `NUMERIC_PARSE_RATIO=0.9`) is the only semantic classifier. All column typing comes from V1 `classify_columns`/`get_semantic_lookup`.

3. **`deep_checks_node` ignores `router_node`'s `suspect_columns`.** It passes `suspicious_columns=None`, so `leakage_check` scans *all* non-target columns. Additionally `leakage_check` skips high-cardinality columns (≥0.9 unique ratio) — the same columns `id_like` flags as leakage suspects — so a suspected ID-like leak column may be silently skipped by the deep check. `suspect_columns` is written to state but never consumed.

4. **PostgreSQL hard requirement.** `main.py` calls `ensure_schema()` / `PostgresSaver` at startup with no SQLite/in-memory fallback (`ARCHITECTURE.md` rates operational usability 5.0/10 for this). The visualizer workbench also requires a past run row in Postgres.

6. **`Finding` model lacks `suggested_fix`** (the brief lists it as a required evidence field; code has `check_name`, `severity`, `evidence`, `affected_columns`, `confidence` only). Minor contract drift between brief and implementation.

7. **Eval harness dependency gap.** `eval/run_harness.py` imports `yaml`, but `pyyaml` is not in `requirements.txt` or `pyproject.toml`.
